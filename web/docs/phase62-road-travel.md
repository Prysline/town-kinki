# 第62階段：原版寶箱載具在四城間的公路旅行、事故耐久與徒步鍛鍊

> **後續更新（第63階段）**：以下「迷路尚未移植」說明是第62階段完成當時的界線；第63階段已根據 [原版迷路與事故後四城改道](phase63-road-lost.md) 補齊該分支，並無損升級第62階段已儲存的行程。原版500元巴士與其他來源車輛仍未移植。


日期：2026-11-22。從第61階段合併的 \`feature/web-dual-mode-phase1\` 提交 \`abb06dd1\` 開發。**不修改原版 \`master\`、CGI 或舊玩家存檔**。第61階段四寶箱抽到的原始33欄道具，這輪新增能真正參與交通，而不是僅顯示於背包。

## 一、原版來源

- \`town_ini.cgi\`：「徒歩で街の移動にかかる時間」\`$matiidou_time='10'\`（徒步10秒）；\`%idou_syudan\` 有20組載具名稱與移動秒數。部分舉例：\`ローラースルーゴーゴー=20\`、\`自転車=15\`、\`スーパーカブ=10\`、\`ドゥカティ=7\`、\`BMW=4\`、\`ポルシェ=3\`、\`フェラーリ=2\`、\`ミグ25=0\`。精確名稱／秒數在執行時全部由來源解析。
- \`town_lib.pl::header\` 原版 \`mati_idou\`：從持有物選出符合 \`%idou_syudan\` 名稱的載具，使用該載具秒數；沒有則徒步。Perl \`each %idou_syudan\` 遍歷雜湊時選出的**第一個**持有載具可能不固定，並非保證最快；Web 改為玩家**明確選擇**本人取得的載具，避免依執行階段雜湊順序猜測。
- 同一來源原版每次公路移動：\`$randed=int(rand($ziko_kakuritu)+1)\`、\`$ziko_kakuritu='10'\`，即約**1/10**發生交通事故；原版若為非徒步，\`town_maker.cgi::login_view\` 事故分支尋找對應持有物，\`$syo_taikyuu --\`，讓其耐久減1。Web 事故抽選／扣耐久全部由伺服器處理，不接受客戶端代填事故旗標或汽車名稱。
- 徒步與腳踏車分支有五次獨立 \`int(rand(15)+1)\`。徒步五種能力（體力、健康、速度、臂力、腿力）中各自抽到**1～5**便增加等於該點數的能力；腳踏車門檻依序是**3、3、5、3、3**，其他情況不加能力。Web 使用伺服器亂數，絕不由客戶端指定提升數值。
- \`town_lib.pl\` 的原版移動顯示 JS 倒數，完成後送至 \`town_maker.cgi\`。Web 使用 SQLite 持久化出發與抵達兩階段；即便步行10秒或載具0秒，也必須由本人明確完成抵達。單純開啟 \`GET /api/state\` 不會偷改城鎮。

## 二、原版迷路分支與這輪實作界線

**重要未移植：原版 \`$maigo\` 迷路及事故造成的迷路。** \`town_lib.pl\` 在前一城不是3時，若持有 \`ローラースルーゴーゴー\` 就設定迷路，否則另有五分之一的迷路抽樣；\`town_maker.cgi\` 迷路分支與傳入的 \`town_no\`、\`maemati\` 舊 CGI 欄位耦合，某些分支會抽新城但未更新目的地欄位。第62階段的 Web **仍以使用者指定目的地抵達**，不虛構或擅自改寫原版迷路轉向的結果。原版的巴士500元支線、道路行動期間的全系統互斥也未補入本次公路載具 API。

本輪只使用 **第61階段新 Web 寶箱來源** \`__web_treasure__\`，必須是 \`dat_dir/otakara.cgi\` 原本存在、與 \`%idou_syudan\` 同名、本人真正持有、耐久大於0、原始33欄不可變設定一致的載具。原版其他商店可能也能取得同名載具，仍需核實其來源後才擴充；禁止僅用請求 JSON 指定「法拉利」就當成已擁有。原版箱子末項本來不可抽，此規則由第61階段保留。

## 三、實際 Web 交易與持久行程

- 新 \`web/src/road-travel.mjs\`：啟動時核對 \`town_ini.cgi\`、\`town_lib.pl\`、\`town_maker.cgi\` 與第61階段原始寶箱110項獎池；單一 \`arcade_road_trips\` 表保存玩家、請求碼、本人當時所在地、目的地、實體道具行號、載具原名與原版秒數、出發／預計抵達時刻、事故、鍛鍊能力結果與正式抵達時刻。一人同時最多一段未結束的公路旅程。
- \`POST /api/road/start\` 只接 \`toTownId\`、\`vehicleSourceLine\`（可省略，表示徒步）、\`requestId\`。伺服器只認已建角色與四座原版城鎮，不能走向自己所在地；在 \`BEGIN IMMEDIATE\` 下鎖定行程、驗證本人33欄載具、抽事故／能力，寫入行程與鍛鍊能力；**事故的1點耐久在出發時就原子預扣**，而非原版於抵達時再扣，避免行程中將道具轉讓／用盡而漏扣。不存在事故就不新增耐久使用紀錄。
- \`POST /api/road/arrive\` 只接本人旅程 \`tripId\`，伺服器根據**遊戲時間**核對 \`arrivalAt\`，未到時間必須拒絕；確認角色仍在出發城市後，原子更新所在地、完成標記，並公布事故及耐久。客戶端無法指定事故結果、目的地、秒數或耐久。
- 同人同一出發 \`requestId\` 只返回已存在旅程，不重新鍛鍊、抽事故或損壞；已完成的同一抵達 \`tripId\` 只重播結果，不再次搬移。旅程未完成時，同一人另一段公路出發及原有 \`POST /api/move\` 電車跨城都被拒絕；其他尚未實作全域行動鎖的 Web 設施仍可操作，這部分不聲稱與原版 CGI 互斥完全相同。
- 玩家移動途中也能關閉瀏覽器；重啟後 SQLite 仍保存行程，時間到時可完成抵達。單機快轉會推進判定時間，但不會跳過手動抵達步驟。畫面每秒更新倒數與完成按鈕，且保留本人最近20次已完成旅程；後端長期保留歷史。
- 事故對原始33欄背包道具只更新既有 \`legacy_item_usage\` 剩餘耐久，保留原始不可變33欄與購入時間；零耐久時依同一 \`inventoryLife\` 生命週期決定不再列於持有物，不會讓事故損毀載具繼續出現在交通選單。
- 原版 \`station.cgi\` 的跨城電車票價及可操作按鈕不受此次公路旅行變動，除「尚有未抵達公路旅程」這項防重疊安全限制外仍可正常使用。
