# 第 37 階段：原版「ギフト屋」物品轉換與跨玩家贈送（2026-11-20）

## 直接來源

- `unit.pl` 第 130 行：原版「ギフト屋」導向 `gifutoya.cgi`，不是百貨購物。
- `gifutoya.cgi`：`$koukan_money=50000`，將本人現有的 33 欄 `mono.cgi` 物品轉為 `ギフト`。輸入數量為 0、未輸入或大於等於耐久時轉全部；低於耐久且大於零則從原物品切出指定回數／天數。日制物品先扣除已過天數並重算起始日。
- `town_ini.cgi`：`$kounyu_gift_gendo=10`（未寄送禮品數量上限），`$gift_gendo=10`（已收禮品數量上限）。
- `command.pl::gift_souhu_syori`：以正整數回／日數寄給其他角色，寄件人禮品扣除份數；收件人獲得 `ギフト商品`，購入時間重算、耐久設成寄出份數、每單位價格改為 0 並追加寄件人說明。同名優惠券的處理是獨立特例，不能直接用一般禮品移轉替代。
- 原版寄送與站內信功能整合。本切片移植禮品資產轉移，**不假裝已產生原版站內信本文／信箱紀錄**。

## 完成功能

1. `web/src/gift-shop.mjs` 新增禮品轉換、寄送與交易歷史。只允許修改本人從 Web 真實購買或收到的 33 欄物品；`original_id` 非 `__web_retail__` / `__web_gift__` 的原版匯入物品保持唯讀。每次變更都驗證原始欄位一致性。
2. **禮品轉換**需角色目前城鎮設有「ギフト屋」，每次單筆現金收費 50,000 元；Web 補上「餘額不足拒絕」保護，原始 CGI 只有 `money -= 50000` 而沒有事前資金判斷，這是明確的安全差異。
3. 轉換全部或切出剩餘耐久的一部分；原始持有物已用過的「回」次數由 `legacy_item_usage` 剩餘量計算，原版「日」耐久按照已過日數處理；禮品與普通物品保留各自容量。
4. **跨玩家寄送**可按角色名稱指定收件人，拒絕送給自己，檢查寄件人是否真有 `ギフト` 及足夠剩餘耐久、收件人是否未達 10 格；收件時新增 `ギフト商品` 與寄件者說明，不會把收件人當成一般百貨購物。
5. 交易在 SQLite `BEGIN IMMEDIATE` 內同時完成寄件人耐久、收件人新物品、手續費、使用表及稽核流水。失敗全部回滾，同一 `requestId` 不能重複扣款、重複送禮或換人重用。
6. 地圖新增 `ギフト屋` 可操作入口，顯示本人可轉換／可寄送物品、數量、收件人與操作歷史；原始匯入物品不列入可修改清單。

## 尚未完成與刻意保留

- **原版站內信**：實際禮品資產可從一名玩家移至另一名玩家，但還沒產生原始 `mail.cgi` 格式與收件／寄件郵件內容，這與原版一鍵附信寄送不完全相同。
- **優惠券特例**：原版會合併已有券並走額外帳簿邏輯，尚未與 Web 優惠券簿完整對接，暫時拒絕透過一般禮品寄送優惠券。
- **舊版玩家物品轉換**：為避免對既有匯入資料進行未驗證的永久改寫，這次不直接變更來源 `mono.cgi` 存檔，即使原版可操作也必須先做安全兼容映射。
- **接收禮物的特殊效果**：新增 `ギフト商品` 的原始欄位，但未重新定義任何未支援的物品效果；現有安全使用白名單仍決定能否使用。
- 原始 CGI 對資金可為負的行為、本次限制為現金足額；舊版特殊時效與跨來源物品的連續堆疊尚未全部等價。實機瀏覽器與原版歷史玩家檔案驗收仍待進行。
