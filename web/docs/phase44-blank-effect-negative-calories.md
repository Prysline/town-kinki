# 第 44 階段：原版「万能,」空效果的普通使用與負熱量（2026-11-21）

## 核對來源與真實規則

1. `basic.cgi::item_do`（約第 2410～2580 行）先讀取 33 欄持有物，依能力欄加到角色狀態；只有明確效果名稱與數值才另改病情、體重或身高。對 `万能,`，逗號後沒有治療幅度，不得自行補成萬能藥的正增幅；其餘能力、熱量、身體／頭腦耗能仍是一般物品使用流程的一部分。
2. 同段原版使用 `$taijuu += $syo_cal / 1000`，未排除負數，所以 `-100 kcal` 對應體重 `-0.1 kg`、`-300 kcal` 對應 `-0.3 kg`。Web 過去在 `parseArchivedItem` 的 `nonnegative` 拒絕負熱量，導致有原版效果的商品不能使用。
3. `dat_dir/syouhin.cgi` 來源：
   - 第 380 行 `関西名産店／琵琶湖の水`：效果碼 `万能,`、外貌／體力／健康各 +10，熱量 -100 kcal、5 回、每次間隔 1 分鐘；原價 10,000。
   - 第 448 行 `書籍／無駄知識を覚える本`：效果碼 `万能,`、國語等七門學科各 +3、其餘七項 +1、LOVE／趣味／情色三項 +5，消耗身體能量 1、頭腦能量 10，5 日、使用間隔 30 分鐘；原價 1,050。
   - 第 227 行 `アルコール／ぼったくり`：效果碼 `無`、17 項能力各 +1，熱量 -300 kcal、身體／頭腦能量各消耗 10，1 回、使用間隔 3 分鐘；原價 15,000。
   - 第 405 行 `金の箱／ランドマスター` 雖然同樣是 `万能,`，其他一般能力與熱量為 0，備註提及移動工具，但現階段尚未核實對應的可執行移動分支；**維持一般物品使用白名單外**，不可因備註推定 Web 已有交通效果。

## 實際移植

- `web/src/legacy-item-use.mjs`：僅對上列兩款確有一般效果的空 `万能,` 商品接受無數值特殊欄位（治病幅度視為 0），仍照原始 17 能力欄位、消耗、間隔、有效天數及耐久正常結算。再放行來源確認的兩款負熱量商品，改採有界帶號整數解析，拒絕任意自填負熱量與同名偽造品。
- 對來源核對逐一比對分類、名稱、特殊碼、17 個能力數值、原價、耐久單位、間隔、初始庫存、熱量、能量、備註及特賣欄；合法交易可變更的耐久、使用時間、購入日期和單價不當作固定來源欄。
- 保持既有 SQLite 交易原子性、請求防重、單件／日制有效期、個別間隔和原始 `mono.cgi` 33 欄唯讀。沒有新增病情診療數值、車輛功能、寵物系統或新設施。
- `web/public/app.js` 對空治療值說明「不能推定治病加成」，負熱量明示使用時依原版減少體重；仍以實際 `supportsLegacyItemUse` 呈現各商品可用狀態。
