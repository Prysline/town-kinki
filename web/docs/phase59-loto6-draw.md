# 第59階段：遊樂中心原版 LOTO6 定時／滿額開獎與普通存款入帳

日期：2026-11-22。開發分支 \`feature/web-phase59-loto6-draw\`，從 \`feature/web-dual-mode-phase1\` 的第58階段整合提交 \`5df346bd\` 開發；不修改原版 \`master\`，也不轉換舊 Perl 玩家檔案。

## 一、原版入口與規則證據

\`unit.pl::ゲーセン\` → \`gamerand.cgi\` → \`loto6.cgi::loto_game\`。這是**另一支**六號樂透，不是第58階段 \`loto.cgi\` 的六位數即時開獎。

| 原版程式 | 可執行設定 |
|---|---|
| \`$loto_n=36\`、\`&randcheck($loto_n,6)\` | 在1～36中選6個**不重複**號碼，開獎排序後顯示；是否中獎不比較位置 |
| \`$koniyukingaku=2500\` | 每注扣身上現金2,500元 |
| \`$hitri_konu_zyougen=20\` | 同一玩家在本輪未開獎彩券最多20注；開獎清空本輪後可再買 |
| \`$saidaisanka=200\` | 待開獎200注時，在下次執行 \`loto_game\` 時觸發開獎，原版是在購買前檢查 |
| \`$koushinjikan=6\` | 原版依 \`localtime\`、日期日數及 \`$higawri\` 旗標，**06:00後當天尚未開獎**時首次存取觸發；不會自行排背景程序 |
| \`@syokin_hairetu=(0,2500,5000,100000,1000000,10000000,100000000)\` | 猜中0～6個**不同號碼**的固定獎金，非倍率 |
| \`$aite_bank += $sougou_syokin\` | 同一玩家的彩券獎金累計後匯到普通存款，並寫 \`ginkoumeisai.cgi\`；不是發現金或再扣本金 |
| \`$in{'randamu_set'}\` | 原版可由伺服器隨機選號，也可手動選六號 |

此 fork 的 \`log_dir/loto_konuu6.cgi\` 與 \`log_dir/loto_kekka6.cgi\` 均為 **0 bytes**。因此 Web 自己建空帳本，不憑空補成既有彩券或歷史中獎號碼。

### 開獎時序要點

1. 玩家進入原版頁面時，先檢查當地時間和現有未開獎彩券；如果當日06:00條件已滿足，或已有200注，**先開獎，再允許購買下一輪彩券**。
2. 第200注買入後不會在當次購券前檢查時就開獎；**下一次進入/操作頁面**才發生滿額開獎。若達到當地06:00但沒有任何待開獎彩券，原版仍會產生當次空場開獎紀錄。
3. 同一當地日期已經因滿額觸發過開獎，06:00不會再無條件開一次；若當日之後再累積200注，仍可在下一次存取時滿額開獎。
4. 若當日06:00已開獎，之後購買的彩券不會立即再次因為時鐘超過06:00而開獎；等下個當地日期06:00，或下一次湊滿200注。
5. 原版 \`$hinichi\` 只記「一個月中的第幾日」，並有特定 \`$koushin > $hour\` 的時鐘倒退分支。Web 使用完整當地 \`YYYY-MM-DD\` 日期與 \`Asia/Taipei\` 時區，避免跨月同日錯判；這是特意保護資料的日期判斷差異。

## 二、Web 結構與資料完整性

- 新 \`web/src/arcade-loto6.mjs\` 啟動時驗證真正原始碼的價格、1～36、6號、滿額200、玩家20注、06:00、七級固定獎金與銀行入帳。
- \`arcade_loto6_state\` 保存最後開獎當地日期；\`arcade_loto6_draws\` 存全部開獎號碼、原因、張數與時間；\`arcade_loto6_tickets\` 存購買人、請求碼、6個號碼、是否隨機選號、購買時間、所屬開獎及中獎號碼數/獎金。每人最近20筆畫面紀錄不會刪除長期帳本。
- \`POST /api/arcade/loto6/buy\`：僅接受 \`{numbers:[六個1～36且不重複],random:false,requestId}\` 或 \`{random:true,requestId}\`。隨機模式由**伺服器** \`crypto.randomInt(36)\` 抽六個不同號碼；同一請求碼重播原彩券、原號碼、不再次扣款，禁止改動選號或隨機／手動模式。購券費2,500元由身上現金扣除，不可讓現金為負。每人每輪20注。
- \`POST /api/arcade/loto6/check\`：玩家在遊樂中心按「檢查／執行開獎」後，符合06:00或200注條件時對**全部玩家**的待開獎彩券，使用同一組伺服器產生的六個不重複號碼結算。抽號完全不採用前端指定結果；每筆彩券用集合交集計中0～6號，固定獎金按原版表。
- 在一筆 SQLite \`BEGIN IMMEDIATE\` 交易中寫開獎、把全部彩券標記結果、完成每一參與玩家的當日銀行利息（如應發）、累計中獎者全部本輪獎金、匯入其**普通存款**及新增銀行帳簿「六號樂透中獎金」。\`banking.mjs\` 只新增可在既存交易內呼叫的 \`settleBankInterestInTransaction\`，避免跨玩家中途另開交易，也避免獎金入帳當天二次生息。
- 任何隨機號碼不合法、銀行金額超安全整數、寫帳失敗、票券存檔異常，都完整回滾現金、存款、銀行帳簿、彩券與開獎；不得只讓贏家領錢但別人沒結算。原始 CGI 允許低餘額扣到負現金，Web 一律要求足額現金。
- 同一輪待開獎張數是全玩家共用，購券、開獎與滿額判斷原子化；每個角色的彩券與中獎資訊只向本人暴露。

### 與原版的明確操作差異

原版在進入 \`loto6.cgi\` 頁面即可能開獎。Web 為避免只讀取任何主畫面、甚至停留在其他分頁時都改動跨玩家銀行帳戶，改成**按「檢查／執行開獎」時**或**下一次購券前**觸發。這不是背景自動排程；超過06:00不保證未登入的玩家自動收到款項，但下一次有玩家觸發會結清全部人的待開獎彩券。獎金0元的玩家不寫空白銀行帳簿項。全域 \`$koudou_seigen\` 五秒 CGI 行動限制並未套到所有 Web 設施，未聲稱完整等價。原版在多人檔案讀寫發生錯誤時可能留下部分結果；Web 將其改成全有全無的 SQLite 交易。
