# 第 46 階段：禮品寄送附帶雙向站內信（2026-11-21）

## 原版 CGI 直接證據

- `command.pl::mail_sousin` 約第 2468～2635 行：寄件頁面有收件人、`m_com` 文字欄及 `gift_souhu` 禮品下拉選單，並以 `okurisuu` 表示寄送回數／日數；原版規定訊息不可留白。
- `command.pl::mail_do` 約第 2828～2940 行：先核對收件人及寄送內容；如有禮品，呼叫 `gift_souhu_syori` 扣除寄件人耐久、建立收件人的 `ギフト商品`；再將收件信寫到 `./member/<收件ID>/mail.cgi`，並在寄件人的 `mail.cgi` 寫寄件備份。兩封信各附贈送品名與份數說明。
- 原版收件紀錄以 `受信<>`、寄件備份以 `送信<>` 為前綴，內容還包含對方名稱、訊息與時間；`town_ini.cgi` 約第 258 行 `$mail_hozon_gandosuu = '50'`，原版單人**收件與寄件合計**最多保存 50 封，超出的最舊信件會被裁掉。
- `command.pl::gift_souhu_syori` 約第 2942～3010 行確實管理物品收發和不同類別的 `クーポン` 特例；優惠券帳本仍需獨立驗證，不能直接把優惠券當普通禮物。

## 本階段實際移植

- `web/src/gift-shop.mjs` 在既有 `gift_events`、`legacy_inventory_items` 基礎上新增 `gift_mail_messages`，寄禮時把**物品扣除、收件人道具產生、寄件備份與收件訊息**寫在同一個 `BEGIN IMMEDIATE` 交易內。任一封信插入失敗則整筆回滾，不能只扣禮物不留信，或只留信不交禮物。
- 紀錄包含本人帳號、寄件／收件方向、對方角色名稱、原始文字訊息、品名、份數及時間。存取一律用驗證後的 `user_id` 過濾，沒有跨帳號讀信權限；每一角色依原版上限只保留最近 50 封**Web 寄禮相關**的收／寄信合計，與保留完整防重用的 `gift_events` 分開儲存。
- 延伸既有 `gift_events` 表的 `message` 欄位：相同 `requestId` 只有收件人、來源、數量、訊息都相同才回傳冪等結果，不再複寫收發信；舊資料表以 `PRAGMA table_info` 判斷後安全新增欄位，舊事件的預設空字串保持原資料。
- Web 既有 `gift/send` API 原先無 `message`；為不破壞既有使用者與測試，**省略訊息**時會自動填入「送給你的禮物」，而新版介面要求輸入並可編輯 1～1,000 字訊息。這是特別記錄的 Web 相容性限制，不等同原版強制填寫日文文字，也沒有重現原版僅檢查 Shift-JIS 的限制。
- `web/src/server.mjs` 對已登入角色的 `snapshot` 增加 `giftMail`，由 `listGiftMail` 根據帳號查詢；`web/public/app.js` 的禮品店增加附信欄位、收寄信閱讀區塊，文字以 DOM `textContent` 呈現，不把陌生玩家提交的 HTML 當可執行標記。
- 寄禮仍只有本人已轉換／購入的 `ギフト` 可使用，原版 `mono.cgi` 歷史匯入檔保持唯讀；不改寫原版 33 欄備份。
