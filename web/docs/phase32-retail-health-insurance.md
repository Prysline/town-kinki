# 第 32 階段：百貨健康保険與醫院保險生效整合（2026-11-20）

> **現行範圍更正**：舊 CGI 玩家存檔匯入與相容性已完全排除；原版 CGI／商品格式只供玩法比對，新 Web SQLite 玩家持有物與交易持續性仍須驗收。詳 [決策](project-scope-no-legacy-player-import.md)。

## 原版來源與既有 Web 缺口

- `dat_dir/syouhin.cgi` 第 356 行：商品「健康保険」，`日用品`、效果「無」、30「日」、原價 10,000；百貨用原版乘三後的售價 30,000。
- 原有 `web/src/inventory.mjs` 的健康保險折扣只看 `inventory_items`，而第 30～31 階段百貨購入實際入 `legacy_inventory_items`，未同步這張保險權益表。結果百貨買了健康保險、醫院卻不認。
- `web/src/health.mjs` 依本人有效保險，把治療費改為原價三分之一（取整）。

## 本階段處理

1. `inventoryCoverage` 以 `inventory_items` 為新的有效期帳本；舊版本已購但尚未同步的百貨保險，僅接受本人真實 `__web_retail__` 購入且 33 欄、期限均一致的資料作為過渡來源。
2. 既有帳本與舊購物資料取最晚有效期限，**不相加重複保險時數**，避免同一份購買既在物品清單又在保險資料中出現時重複計算。
3. 之後在實體百貨購入「健康保険」，於同一 SQLite 寫入交易中扣庫存、付款、入物品、延長 `inventory_items` 的保險權益；若與既有直購合計超過五份耐久則整筆回滾。
4. 原本健康保險直購仍可續保，但會從有效期限共同帳本（含舊版購物的過渡資料）計算，避免覆寫既有保險。
5. 醫院詢價、醫療費、保險概況和百貨購入後的個人狀態會立即看到相同結果。僅保險折扣，不聲稱該商品可使用 `legacy-item-use.mjs` 的其他特殊效果。

## 限制

- 舊第 30 階段若在同步前購入多筆彼此獨立的健康保險，不推測原本應當如何把其期限相加，只採用已能驗證的最晚一筆到期日；保留物品原資料以供人工追查。
- 健康保險期限與 Web 購入紀錄必須一致，不能重複計算。**原版舊玩家的保險存檔轉換已排除產品範圍**。
- 其他物品的裝備、贈送、合成、販售及未證實的特殊效果仍未移植，依既定順序逐項處理。
