# 第63階段：原版公路迷路、事故後改道與第62階段行程無損升級

日期：2026-11-22。從第62階段合併後的 \`feature/web-dual-mode-phase1\` 提交 \`8de151b6\` 新開分支 \`feature/web-phase63-road-lost\`。只修改 Web 子目錄，不修改原版 \`master\`、Perl CGI 程式或原始玩家存檔。

## 逐行核對的原版迷路規則

\`town_lib.pl::header\` L541～552：\`mati_idou\`／\`mati_idou2\` 先依來源 \`maemati\`（出發城鎮）判斷是否迷路：

1. \`if ($in{'maemati'} != 3)\`：只有**出發城不是 3** 才執行迷路判斷。出發城 3（原版和歌山島）永遠不會執行此段。
2. \`&motimono_kensa_ev('ローラースルーゴーゴー')\`：若持有這項載具，\`$kensa_flag == 1\`，則 \`$maigo='yes'\`，**必定迷路**，即使實際用另一台車／徒步也一樣。Web 為來源安全，只辨識持有者本人從第61階段原版寶箱取得的、耐久未用盡、不可變33欄與原始獎池相符的這項載具；原版其他商店來源要等來源驗證才能計入。
3. 其他人走 \`int(rand(5)+1) == 1\`，每次 **1/5** 機率迷路。Web 使用伺服器加密安全亂數，不讓客戶端指定迷路、事故或城市。
4. 公路事故仍依 \`town_lib.pl\` 的 \`int(rand($ziko_kakuritu)+1)\`，\`town_ini.cgi\` \`$ziko_kakuritu=10\`；第62階段已實作非徒步時約 1/10 事故，扣實體原版載具一點耐久，並有徒步／腳踏車鍛鍊。
5. **同時迷路且出交通事故**：\`town_maker.cgi::login_view\` L316～319 在事故區塊內 \`$no_rand=int(rand(4))\` 並將 \`$in{'town_no'}=$no_rand\`，回傳的頁面／後續登入使用被重新抽出的四城目的地（可以抽到原出發地、也可以抽回原指定目的地）。Web 計算並保存這個實際目的地，完成旅程後更改角色所在地。
6. **迷路但沒有交通事故**：\`town_maker.cgi::login_view\` L326～329 雖然同樣 \`$no_rand=int(rand(4))\`，卻**沒有** \`$in{'town_no'}=$no_rand\`！\`&message(...,"login_view")\` 又會在 \`town_lib.pl::message\` 直接 \`exit\`，因此這筆亂數沒有實質導航作用，後續回到指定 \`town_no\`。Web 保留「迷路」紀錄，但**仍抵達原定目的地**，絕不把抽出的未使用亂數當作真的傳送。
7. 原版已存在的巴士 \`mati_idou2\` 會覆寫 \`$maigo='no'\`；該項500元巴士仍未納入 Web 公路旅行，此階段沒有擅自宣稱巴士也有迷路。
   
資料來源檢查依 \`town_ini.cgi\`、\`town_lib.pl\`、\`town_maker.cgi\` 的實際迷路條件、5分之1亂數、四城改道與事故分支拒絕靜默來源變更。第62階段的20種載具秒數與1/10事故規則保留。

## Web API／資料相容性

- 延用 \`POST /api/road/start\`、\`POST /api/road/arrive\`，**不增加客戶端可偽造的迷路參數**。伺服器以本人角色 \`town_id\` 判定出發城、合格持有物來源與真正持有耐久；預計抵達時間仍只依第62階段原版載具秒數。所有抽選、事故預扣耐久、能力鍛鍊與新旅程使用同一筆 \`BEGIN IMMEDIATE\` 交易。
- 既有 \`arcade_road_trips\` 增加 \`requested_to_town\`（使用者原定目的地）、\`lost\`（迷路）、\`rerouted\`（原版事故且迷路、實際目的地重新抽選），\`to_town\` 保存**最終抵達地**。已有第62階段表格的 SQLite 以 \`PRAGMA table_info\` 條件式 \`ALTER TABLE\` 無損升級；舊紀錄 \`requested_to_town=to_town\`、\`lost=0\`、\`rerouted=0\`，不重算、不改寫既有行程的原始城鎮、事故或鍛鍊效果。
- **尚未抵達的旅程**：公開快照與開啟回應中 \`toTownId\` 仍是原定目的地 \`requestedToTownId\`，不公開 \`lost\`、\`rerouted\`、\`accident\`、\`durabilityAfter\`；不能由前端提早預知真正改道結果。SQLite內實際獎勵結果早已保存，即使重啟也不再重抽。
- **已抵達**：回應 \`toTownId\` 是確定的實際目的地，另回傳 \`requestedToTownId\`、\`lost\`、\`rerouted\`、\`accident\`；介面可明白指出事故迷路後是否被改道、是否剛巧抽回原目的地，以及只出現迷路提示但沒有改道的原碼行為。旅程重送不再次轉向或扣耐久。
- 個人最近20次公路紀錄保留事故、迷路及改道標記；他人無法取得本人未抵達旅程；從和歌山出發不迷路、跨城電車不可與公路未完成旅程並行等安全限制維持原狀。

## 對第62階段的可觀察變化與尚未處理

- 過去第62階段公路目的地即使用者選擇的地點；現在在「事故＋迷路」才可能真正隨機改道。一般徒步的迷路抽選不會改道，因原版只有非徒步的事故處理分支會真正覆寫目的地。
- 持有「ローラースルーゴーゴー」時，應依持有而非選用判定是否必迷路；Web 目前只會信任第61階段真正開箱並寫入的寶箱來源，其他可能從商店取得的同名道具還待核對。
- 原版 Perl 無序 Hash 自動選第一台持有車、原版500元巴士及各 CGI 間其他未移植規則依然不等同 Web。Web 繼續採用第62階段玩家明確選車、出發時先預扣事故損耗與真實SQLite持久行程的安全設計，沒有假稱完全一致。
- 沒有實作新的魔法、裝備、特殊寶箱道具的未知用途。原版 \`master\` 及21格單機試玩城鎮維持不變。
