- obatyan.cgi::week / strong / battle：弱（原始 mode 為 week）與強各抽五名原版 NPC；先攻速度嚴格大於對方，最多 50 次攻擊；對方身體、對方頭腦、自己身體、自己頭腦依序判敗。

- kougeki / kougekinaiyou / iryoku_hantei：16 種均勻攻擊，原能力欄索引 1–9、11–17（健康不直接攻擊）；攻擊 1–8、14 為精神，其餘身體；傷害為攻方指定能力減守方相同能力，最低零。無 B 聯賽裝備機制。
- 每次攻擊基礎金額弱 300、強 1000；勝利乘五，失敗扣基礎累計，平手無金錢。原版無 K 點獎勵。Web 核心沿用非負現金安全界線，另保留原始差額。
- get_itm：每種難度各四筆宣告；Web 已經使用者確認，依下述相容性修正均勻抽選全部四筆。容量 25 格檢查先於同分類同名堆疊；實際入庫尚未接線。

## 相容性修正：獎品抽選上限
- 原版證據：obatyan.cgi L159–160、L170–171 兩種勝利分支均為 `int(rand(3))`，註解「準備して有る数」「0～準備して有る数-1」意指已準備獎品數量及其索引範圍；get_itm L390 起的弱／強陣列實際各有四筆。第四筆知恵袋具完整效果欄，原版執行卻不可達。
- 判定：疑似新增獎品後未更新抽選上限，作者意圖未能證實。經使用者確認，Web 作相容性修正，不改原始 CGI。
- 原版索引 0、1、2 各 1/3，索引 3 為 0%；Web 以 `draw(rng, prizes.length)` 抽選，現有索引 0–3 各 25%，弱版「おばちゃんの知恵袋」與強版「おばちゃんの知恵袋（スーパー）」均可抽中。日後經來源審核加入獎品時，抽選上限隨陣列長度改變；來源解析仍核對目前原始四筆陣列。
- 原版抽選上限以 `originalDropChoices: 3` 保留作來源紀錄，不參與 Web 抽選。測試驗證兩種難度每個索引、動態長度及敗北／平手不抽獎。此修正不改獎品效果、原始欄位、金錢、容量、勝負條件；異常「おばちゃんの力」仍原樣保留，尚未接入背包。
 
## 阻礙與不做假設
town_lib.pl::weekobalog / strongobalog 讀取 member/osaka/w1log.cgi ～ w5log.cgi、s1log.cgi ～ s5log.cgi。整合分支逐檔取得均回傳 404；master 上抽查 w1/s1 亦 404。dat_dir/obatyan.cgi 查詢也為 404。程式沒有內嵌對手能力值。不能以全零、隨機能力或玩家資料冒充原版 NPC。
 
核心只讀十個指定 NPC 路徑，解析時僅投影原名與 17 能力，不回傳私人資料欄；任何檔案缺失都關閉整個目錄。測試使用明確標為 TEST 的臨時資料，不提供正式 NPC。
 
弱獎品「おばちゃんの力」效果欄為「無3」，能力等欄存在異常；強同名獎品缺少正常效果欄，導致耐久索引 21 為「回」而 22 為「30」。保留原始位置，標為不可直接解析使用，不憑名稱修復。兩難度同名獎品效果不同，而 CGI 同名堆疊保留既有欄位；未接入背包前需單獨處理安全相容。
