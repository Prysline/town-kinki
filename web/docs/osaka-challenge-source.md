## 阻礙與不做假設
town_lib.pl::weekobalog / strongobalog 讀取 member/osaka/w1log.cgi ～ w5log.cgi、s1log.cgi ～ s5log.cgi。整合分支逐檔取得均回傳 404；master 上抽查 w1/s1 亦 404。dat_dir/obatyan.cgi 查詢也為 404。其他可列出的分支 i18n/web-remaining-visible-text-zh-tw、test/web-db04-pr42-gift-ledger-restore、feature/web-b-league-arena 抽查 w1 同樣 404；提交關鍵字 osaka、obatyan、member/osaka、w1log.cgi、大阪 未找到結果。連接器沒有按檔案路徑列完整 Git 歷史的功能，不能據此聲稱所有歷史提交皆無資料。程式沒有內嵌對手能力值。不能以全零、隨機能力或玩家資料冒充原版 NPC。
 
核心只讀十個指定 NPC 路徑，解析時僅投影原名與 17 能力，不回傳私人資料欄；任何檔案缺失均不啟用部分原版目錄；預設 auto 改用獨立重建池。格式異常則停用挑戰而不讓整個伺服器無法啟動。管理者可設定 OSAKA_NPC_ROOT 指向可信原版 NPC 資料根目錄，其下必須為 member/osaka/w1log.cgi 等十個固定檔名；預設為 repository root。由部署管理者配置，不是玩家可傳的 API 參數；測試使用明確標為 TEST 的臨時資料，不提供正式 NPC。

## Web 整合與驗收
- 地圖兩入口（おばちゃん／おばちゃん強）及ゲーセン遊樂中心同一挑戰面板；缺原版資料時依管理者策略顯示重建版來源或禁止挑戰。單機可編輯地圖，多人使用已配置城鎮；初始地圖與現有存檔不改。
- POST /api/osaka/play 僅接受 mode、requestId；伺服器由登入身份、目前城鎮、可信 NPC 目錄與亂數決定結果。不接受自訂對手、傷害或獎品。兩難度共用 5 秒大阪行動冷卻（原版 town_ini.cgi 的全域 5 秒限制，Web 未建立跨模組全域鎖）。
- SQLite BEGIN IMMEDIATE 原子保存角色能量、現金、背包及 osaka_battles 收據，依本人 requestId 防重、同 ID 不可更換難度；本人最近 20 局及最新逐次攻擊。刪除單機帳號遵循外鍵級聯；無私人 CGI 寫入。
- 測試含原版核心、完整獎品各索引、正常獎品實際使用、已確認欄位修正及舊待核對格遷移、同名堆疊、容量、冷卻、回滾、重啟、單機／多人 HTTP、偽造參數及地圖入口。CI 結果以 PR Actions 為準。
- 原版十筆仍未取得，不宣稱重建版是原始對手；Web 已提供標註的獨立重建玩法，真人瀏覽器驗收仍待進行。兩筆獎品欄位修正已確認。

## 經使用者授權的 Web 重建 NPC v1
原版十筆專用 NPC 資料仍缺失。重建內容是新增設計，不是史料復原，不寫入 member/osaka，不使用 TEST 夾具或玩家資料。獨立資料集 web/src/osaka-npc-reconstruction.mjs；版本 web-osaka-npc-v1。每名 NPC 固定十七項能力，弱五名、強五名各等機率；原版傷害、能量、先攻、50 次上限、獎金、掉落、冷卻規則不變。

設計基準：engine.mjs 的初始配點頭腦 200／身體 200／其他 100、預設每項 20；原版 dat_dir/school.cgi 單次專科 +8～14、gym.cgi 日常訓練單項 +0～5，job.cgi 便利店店員等入門職業有 50～60 門檻，店長等約 100～120。由此選擇弱對手單項 20～38、強對手 66～112，按市場／街坊／運動／歌唱／料理五種專長微調。不代表原版數值，也不是固定玩家等級門檻。新手全 20 不適合直接挑戰，弱組供初期訓練後挑戰，強組供中期成長後挑戰。實際傷害依每項能力差、兩種剩餘能量及隨機攻擊而定。

部署策略：
- OSAKA_NPC_POLICY=auto（預設）：完整且可解析的十筆原版專用檔案優先；只要缺檔，整組使用十名重建 NPC，不混合；若存在檔案無法讀取或解析，停用並顯示異常，不掩蓋錯誤。
- OSAKA_NPC_POLICY=original-only：僅完整原版專用目錄可用；缺檔或異常即停用。
- OSAKA_NPC_ROOT 保持原有部署設定；標示 original-file 表示讀取管理者提供的固定原版路徑及欄位通過驗證，不是對外部來源真偽的密碼學證明。部署者需核對實際來源。切換須重啟；玩家不能指定策略、來源或 NPC。
- 狀態 API npcSource、npcSourceVersion、npcPolicy；每局 SQLite 收據固定記錄 npcSource、npcSourceVersion 和完整當局 NPC 投影，歷史不隨後續來源切換重標。舊版無來源標記的收據顯示來源未記錄；不推論成原版。
- UI 開戰前確認、狀態、結果及近期歷史均顯示來源（重建版明示非原版與版本）。
- 校準測試使用正式 rollOsaka 和固定種子，每種難度／均衡能力點數各 2000 局，全滿能量；不是實際玩家勝率或營運經濟驗證。測試另驗證來源切換、缺檔／部分／異常、兩模式 HTTP、帳號隔離、舊收據及防重。
