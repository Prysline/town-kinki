# 第 30 階段：職業、教室／訓練、公開個人檔案逐函式來源盤點

> **盤點時間**：2026-11-20；比較基準：`feature/web-dual-mode-phase1`（首次來源查核於 PR #17 後，PR #18 已整合）。**本文件為逐項原版來源查證，不是已移植或瀏覽器驗收聲明**。除了原始 CGI／資料表明確存在的流程，不新增假定的功能。以下「確定缺漏」僅指已找到原版操作分支而 Web 沒有對應行為；「資料／說明存在、執行缺口」不視為已驗證的遊戲規則。

## 4. 逐項處理次序與證據門檻

1. **先修已確認的使用者可見缺漏**：WK-04 原版 17 項職業需求、玩家目前值、BMI／薪資等全表，因資料已在 `parseLegacyJobs` 中且 UI 只需補完整展示。此工作以 150 筆原始 `dat_dir/job.cgi` 核對。
2. **工作結算數值**：WK-05 薪資去向要連動現存銀行交易明細；WK-06 性別／身高工作時重驗的差異需先建立來源案例，**不默默改掉既有安全檢查**。
3. **教室獨立移植**：TR-04～TR-06 用 `kyushitu.cgi` 的 4 筆原版課程與真正公式；分別測試能力、兩種能量、減重、分鐘冷卻、付款、銀行帳簿、重送與多帳號隔離，不挪用健身房的設定。
4. **其餘原版操作**：WK-07 玩家投稿職業需獨立的審核／權限考量；SC-04～05 真實個人檔案須先確認自願公開與個資安全，無真實備份時只做來源與合成測試。
5. **不建立功能的項目**：只有未解析效果字串、未確認實際 CGI、或無既有資料欄位的推測，**不得標成「漏移植」或安排 P0/P1/P2 工作**。

**本輪工作性質**：重新查閱、逐段驗證並補上可追溯的來源；尚未修改 Web 遊戲程式、SQLite、角色資料或原版 `master`。
