# 第 35 階段：原版裝備屋交易、獨立倉庫與換裝（2026-11-20）

## 原版來源

- `unit.pl` 第 144 行：城鎮地圖 `装備屋` 進入 `hanbai.cgi::hanbai`。
- `hanbai.cgi` 第 6 行：商品來源為 `dat_dir/soubi.cgi`，不是百貨 `syouhin.cgi`；每筆 **6 個主要欄位**（類別、名稱、威力、命中率、現金售價、使用次數），來源第一列為標題。此份來源共有 **27 件**真實商品，分為「武器、防具、魔法、御守」四類。
- `hanbai.cgi::buy`：原始定價不乘三，不從銀行扣款，且 `money <= price` 也視為餘額不足；已穿戴或倉庫已持有的同名商品不得重複購買。成功後倉庫建立 **7 個資料欄位**（類別、名稱、威力、命中、使用次數、等級 1、經驗 0）。
- `hanbai.cgi::soubi_do`：一次只穿戴同種類一件，換裝後舊裝備退回倉庫；`soubi_uru` 只從倉庫出售，回收價為 `原價 / 10 × 等級`。
- `basic.cgi` 原始 `$oyatu_kisei = 'no'`；飲料全局共用冷卻邏輯雖有分支，在這份 fork 預設不啟用。Web 保留現有道具自身冷卻，不另加虛構的跨飲料鎖定。

## 新增功能

1. `web/src/equipment.mjs` 嚴格解析原始裝備資料，獨立建立 `equipment_items` 與 `equipment_transactions`。所有裝備不混入原版 33 欄一般持有物，也不假裝既有 `mono.cgi` 的 7 欄歷史裝備已成功匯入。
2. 伺服器提供 `/api/equipment/buy`、`equip`、`sell`，只有角色目前所在城市實際設有 `装備屋` 才允許執行。所有扣現金、倉庫與換裝狀態、交易記錄在同一 SQLite `BEGIN IMMEDIATE` 內提交；使用 `requestId` 防止重送重複扣款或再售出。
3. 商品單件現金購買，保留原版嚴格大於售價的條件及同名拒購。倉庫和已穿戴裝備分開顯示；換裝只更換相同分類，舊裝備歸倉，防止其他帳號挪用物品。
4. 只有**尚未穿戴的本人倉庫物品**可出售。原始 Perl 的售出公式可能產生小數（例如原價 105 的 10.5 元）；Web 的現金記錄使用整數，**向下取整**，為已說明的格式適配而非完全原樣的金錢精度。
5. 地圖 `装備屋` 已可導入獨立 `equipment-panel`，查原版商品、購入、換裝、出售、本人交易紀錄；尚無該建築時不可直接買賣。

## 尚未宣稱完成

- **鍛造**：原版 `hanbai.cgi::kajiya_do` 有等級、經驗及費用邏輯，本階段未移植，也不增加虛構升級。
- **實際戰鬥效果**：裝備狀態已保存，但 Web 尚無對等戰鬥／裝備數值消耗與勝負結算；不可把「已穿戴」當作「戰鬥已套用裝備能力」。
- **歷史存檔**：原版裝備倉庫本身是 7 欄，現有一般持有物匯入器只解析 33 欄；本次不擅自併檔。原始角色預設「素手／洋服／念力／先祖の霊」等裝備欄也還沒完整遷移。
- 原版倉庫出售價格如有小數，本次做整數截斷；與 Perl 原始浮點值不是全等。實機瀏覽器、真實舊角色與其他多人關聯檔仍待驗收。
