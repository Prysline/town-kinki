# 第 36 階段：原版裝備屋鍛造（2026-11-20）

## 原始執行依據

- `hanbai.cgi::kajiya`：裝備「武器、防具、魔法、御守」分別列出倉庫與穿戴中品項，原版為威力與耐久選擇 1、3、5、10、15、25、50，或「不增加」。
- `hanbai.cgi::kajiya_do`：至少選一項；`hiyou = iryoku_up * 10000 + taikyuu_up * 1000`，`hiyou > money` 才拒絕，因此現金剛好足額時可鍛造（不同於裝備購買的現金需大於售價）。
- 強化會更新原版裝備六個固定屬性中的威力、使用次數，不改命中率、等級或經驗。無論裝備當前在倉庫或角色身上，原始程式都有相對應的更新分支。

## 新增

1. `web/src/equipment.mjs::forgeEquipment` 使用 `FORGE_INCREMENTS=[0,1,3,5,10,15,25,50]` 嚴格白名單，至少一項非零；現金扣款、裝備屬性變動及交易記錄在同一筆 SQLite `BEGIN IMMEDIATE` 內完成。
2. 僅本人持有、未出售的裝備且角色目前城鎮確有 `装備屋` 可操作；保留同品基本資料和已穿戴／倉庫狀態，強化數值加入 `requestId` 的防重簽章，重送不重複扣錢或增加屬性。
3. Web 設定額外的單項裝備屬性安全上限 1,000,000，為防止無限次強化造成整數溢位的實作保護，而非原版已證實的上限；拒絕時不扣款。
4. `/api/equipment/forge` 及裝備屋介面支援選擇威力、使用次數、即時費用與付款確認。倉庫和穿戴中的裝備都能強化。

## 仍未實作／保留

- 原版戰鬥對裝備的傷害、命中、使用次數耗損、經驗與等級成長；鍛造後的威力數字已在裝備倉庫中生效，但尚無 Web 戰鬥可使用它。
- 7 欄原版歷史裝備檔匯入、原版初始穿戴欄位、實機瀏覽器與真實玩家存檔驗收。
- 原始 GUI 含預設穿戴「素手／洋服／念力／先祖の霊」；Web 尚未在未有戰鬥時假造這些裝備的戰鬥能力。
