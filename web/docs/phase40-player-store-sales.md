# 第 40 階段：原版住宅玩家商店對外零售（2026-11-20）

> **現行範圍更正**：舊 CGI 玩家存檔匯入與相容性已完全排除；原版 CGI／商品格式只供玩法比對，新 Web SQLite 玩家持有物與交易持續性仍須驗收。詳 [決策](project-scope-no-legacy-player-import.md)。

## 原始依據與交易範圍

- `original_house.cgi::houmon` 的住宅「お店」內容有一張對外貨架；原始資料來自屋主的 `member/<ID>/omise_log.cgi`。進貨仍由 [第 39 階段問屋](phase39-wholesale-store.md)完成，且店主在該建築的住宅室內啟用類型 `1` 才可對外營業。
- `original_house.cgi::omise_settei`：原版基本售價倍率 `$omise_yobi5` 預設為 **2**。非超市按商品進貨原價 ×2；`スーパー` 先將基準價 ×1.5，再乘 2。店主可以於 `my_syouhin` 將個別售價改為進貨基準的 **1/10～3 倍**；超市的進貨基準先乘 1.5，所以超市自訂價上下限實際相當於原始批發標價的 0.15～4.5 倍。原版可接受半元小數，Web 目前只接受整數，最低以向上取整、最高以向下取整。
- `command.pl::buy_syouhin`：客人最多持有 25 格一般物品與 10 格購入禮品；同名物品按「回」／「日」耐久合併，上限五份。商品從店鋪共用庫存扣除，買家以現金或本人有效原版信用卡從普通銀行付款；非店主購買時，賣家普通銀行收到**完整銷售額**，並寫入普通帳簿。若買家自有住宅所在城鎮與店鋪相同，且非在本人店內購買，另有**成交金額 10%（取整）的現金回饋**。
- `town_ini.cgi` 目前 `$kaenai_seigen='0'`，因此原版目前並未全面禁止屋主自買。Web 允許屋主自己購物，但不讓同一帳戶賣給自己時憑空產生銀行收入／同城回饋。

## Web 此階段的實際功能

- `GET /api/shop/visit?houseId=...`：驗證訪客角色、當前所在城鎮、住宅存在、原版室內 type `1` 且店鋪已設定，傳回對外商品、庫存與由後端計算的售價，**不外流完整原始商品存檔**。
- `POST /api/shop/price`：只有店主可以按該商品的原始基準價上下限修改售價，`player_shop_stock.sale_price` 以資料庫遷移欄位留存。未修改時保留原版預設倍率。
- `POST /api/shop/buy`：真正的店鋪交易，檢查庫存、角色餘額、信用卡及持有容量；支援每次 1～5 件、本人 Web 商店購入物品「回」／「日」耐久續購（原始外部匯入檔不改寫）、共用貨架扣量、買家 33 欄物品入庫、店主銀行入帳與帳簿、同城回饋，均在**一筆 SQLite BEGIN IMMEDIATE** 交易內提交。使用 `requestId` 防重與資產回滾。
- `player_shop_sales` 留存購物與售出紀錄，買家和店主各可看到自身交易歷史。舊來源不與新來源衝突，原始 CGI 歷史檔保持唯讀。
- 住宅室內「玩家商店」現在會列出真正的對外商品、價格、購買數量與付款方式。屋主也可以直接在商品上調整售價，仍可由問屋頁管理自己的進貨和退貨。
- 玩家商店購入的 33 欄商品來源 `__web_store__` 被明確加入本人可操作持有物來源，讓已驗證的使用、禮品轉換及回收功能可連續操作，而非只顯示不可使用的收藏品。

## 尚未完成／與原版有差異

- 原版完整 `omise_ini.cgi` 的背景 CSS、刊頭備註、全店預設倍率編輯、單商品備註、營業報表及配偶代管尚未搬完；此階段重點是安全可核對的**零售資產交易**。
- 原版可能出現半元小數，Web 金融系統為安全整數，所以自訂價範圍及價格計算有明確的取整處理。
- 只操作 Web 新玩家正式建置、問屋進貨的店鋪庫存；原版 `omise_log.cgi`／`omise_ini.cgi` 只作玩法格式參考，不匯入舊玩家店鋪歷史。
- 「日」耐久的跨平台同名重複堆疊、商品別名／特例、都市經濟力成長與更完整的原版活動事件仍需另外核實。
- 尚待真正瀏覽器操作及新版 Web 玩家商店庫存、交易紀錄在重啟後的驗收。
