# 第54階段：單機優先——原版合成屋與材料交易

日期：2026-11-21。開發分支 `feature/web-phase54-solo-crafting-house`，目標整合 `feature/web-dual-mode-phase1`；原版 `master` 不修改。

## 原版來源（不得把 Web 安全擴充寫成原作規則）

- `unit.pl` 原版「合成」地圖入口對應 `gouseiya.cgi`。
- `gouseiya.cgi::gousei / gousei_do` 讀取本人 `mono.cgi` 持有物耐久，從 `dat_dir/gousei.cgi` 選配方與製作數量；合成手續費為 0 元，成品按配方 33 欄的耐久產出。
- `dat_dir/gousei.cgi` **實際有12種配方**，前七種產出每組1回，後五種每組5回。材料有兩或三種：原始內容以 `成品=材料:用量+...` 形式寫在商品名稱欄。清單依原檔順序：
  1. アイスコーヒー＝冷蔵庫1＋コーヒー1
  2. ホットコーヒー＝ポット1＋コーヒー1
  3. 焙煎アイスコーヒー＝冷蔵庫1＋コーヒー豆1
  4. 焙煎ホットコーヒー＝ポット1＋コーヒー豆1
  5. ミルクコーヒー＝ポット1＋コーヒー1＋ミルク1
  6. アイスクリーム＝冷蔵庫1＋ミルク2
  7. シロノワール＝クロワッサン1＋アイスクリーム1＋シロップ1
  8. 健康汁＝おばちゃんの力1＋青汁1
  9. 韓国語を習う本＝おばちゃんの力1＋おばあちゃんの知恵袋1
  10. 阪神タイガースの選手のレアなサイン＝おばちゃんの力1＋阪神タイガースの公式チケット1
  11. 万能おばちゃんロボット1号＝おばちゃんの力5＋おばあちゃんの知恵袋5＋おばあちゃんの知恵薬（スーパー）5
  12. 純金製ミグ25＝金塊5＋ミグ25 5
- **原始第6筆資料異常**：實際為 `アイスクリーム=冷蔵庫:1:+ミルク:2`，多餘冒號。原始 Perl `split /:/` 仍取 `冷蔵庫` 和 `1`；Web 只接受這筆已核對例外並以相同意義處理，不修改原始資料檔、不忽略其他未知格式。

## Web可操作流程

- `src/crafting.mjs` 啟動時解析原版12種商品完整33欄，不接受前端自己送入成品／效果／定價。
- 新單機試玩城鎮 D8 增加「合成」建築；原本19格成20格，其他172格空白。只對**尚無地圖且無住宅**的城鎮提供玩家自願初始化；已存在的地圖一律不覆蓋。玩家也可使用原版地圖編輯器自行擺放「合成」。
- 地圖「合成」開啟 `public/index.html` 的 `crafting-panel`，列出配方所需材料與本人實際持有量、目前可製作的組數、製作數量及紀錄。沒有合成屋時不可製作。
- `POST /api/crafting/make` 只接受 `recipeKey`、1～99組的整數 `quantity`、`requestId`，其中製作上限還受材料與成品容量限制。本人從不同合法來源取得的同名「回」耐久材料可以依序消耗；材料若為「日」耐久，不臆測可取代原版回數扣除。
- 用 `BEGIN IMMEDIATE` 一起驗證建築、材料真實33欄、本人持有及容量，在同一筆 SQLite 交易寫入使用帳本、合成成品與不可重複交易紀錄；同請求重送只回傳已提交結果，不能換商品或數量；任何失敗全部回滾。
- 合成品記錄 `__web_crafting__` 來源、完整原版33欄、實際製造時間及耐久，物品清單可見其真正剩餘回數；產出的アイスクリーム可繼續當シロノワール的材料。原材料仍按正式 `legacy_item_usage.remaining` 顯示，不能假裝扣除後還有完整耐久。
- Web 安全上限：一般背包最多25個有效項目；同一種已合成成品最多堆疊5組；缺材料、超上限、跨玩家來源及錯誤輸入一律拒絕。保留既有現金，不收合成手續費。此安全邊界與原版同名多筆及全域行動限制的所有細節仍需繼續比對，**不宣稱100%等價**。
