# 第 43 階段：原版ランダム品的實際隨機使用（2026-11-21）

## 原版程式證據
- `dat_dir/syouhin.cgi` 第 113 行是「薬／ランダム品」，原價 2,000,000，17 個能力增幅欄全部為 10，特殊欄為「無」，耐久 10 回、使用間隔 3 分鐘，身體與頭腦消耗皆 0。
- `basic.cgi::item_do` 約 2470～2510 行先為每個能力欄分別執行 `int(rand($syo_XXX + 1))`，再套用抽到的值，最後還原原物品欄位；因此「10」是**每項抽選上限**，不是固定 +10，且每次使用都重抽。
- 原版對一般「回」制物品每次成功使用後扣 1 回，且仍檢查個別使用間隔與身體／頭腦能量，不存在「抽到 0 可以退回一回」規則。百貨售價依原版三倍為 6,000,000。

## 本階段實際變更
- `web/src/legacy-item-use.mjs` 僅在原版「薬／ランダム品」的名稱、分類、17 欄增幅上限、原價、效果、間隔、熱量、消耗及備註與 `syouhin.cgi` 相符時，開放此前被整類拒絕的獨立隨機效果；保留原物品 33 欄唯讀，持有物單價、購買日和已合併的耐久不誤當成不可變來源欄。
- 正式使用透過 Node.js `crypto.randomInt(上限+1)` 逐項抽取 0～10 的整數，結果寫入既有使用歷史與角色能力，扣一回耐久、保留原版個別 3 分鐘間隔及交易防重，資料庫提交失敗整筆回滾。測試可注入可重現的抽選函式，但 HTTP 端不接收也不傳遞任意亂數。
- `web/src/retail.mjs` 及 `web/public/app.js` 將百貨商品標成可真正使用，明確顯示「每項獨立隨機 +0～+10」，不把原版欄位 +10 誤呈為必得數值。

## 驗證範圍
- 單元測試用原始商品表資料驗證 17 項最小值 0、最大值 10、中間值 5、間隔、扣回數、重送同結果、原始 33 欄不變，以及異常亂數的整筆回滾。
- 偽造分類、上限、原價、間隔、特殊效果與能量的變體都不應通過使用白名單。
- 百貨來源與 UI 測試核對商品價格、來源行號及亂數語義；HTTP 測試完整走百貨入店、買入、持有物使用、角色能力更新及防重。

## 尚未全等
- 這次只新增原版確實存在的 1 種「ランダム品」特殊計算；`万能,` 空數值、寵物、禮品信件／優惠券特例、特殊設施與歷史玩家舊檔仍需要獨立核實，不新增未證實的功能。
- 百貨每日抽選上架，並非每次登入都可買到這款昂貴道具；測試以已上架且現金足額情境驗證購買。
