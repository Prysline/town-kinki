# 專案現行範圍：只重製原版玩法，不移轉舊玩家存檔

> 2026-11-21 使用者已明確決定：**原版 Perl／CGI 舊玩家存檔匯入、轉換、相容和驗收完全不在本專案範圍內**。此決策取代第11～51階段所有把舊玩家資料匯入列為待辦、完成標準或相依條件的敘述。後續文件必須遵守；舊階段仍可保留原始 CGI 來源與歷史做法，但不能重新把舊存檔轉移放回待辦。

## 必須做的

1. 以原版 `town_ini.cgi`、`unit.pl`、`basic.cgi`、`coupon.cgi`、`sea.cgi`、`event.pl`、`dat_dir/*.cgi` 等**程式與商品資料**核實玩法：角色能力、冷卻、金錢、機率、建築、交易、耐久、獎品及可達條件。原版 33 欄**商品格式**與新 Web 真實持有物仍可沿用，這不等於轉移舊玩家的 `mono.cgi`。
2. 持續完成單機可玩的流程：**新建角色 → 工作／學習 → 商店 → 背包／消耗 → 住宅／事件／券 → 釣魚／合成／遊樂中心等有原版執行證據的玩法 → 儲存及繼續**。單機新功能優先於多人擴充；已實作的多人權限與資產安全不能破壞。
3. 確保**新版 Web SQLite 存檔**的非破壞性升級、備份／還原、角色資產一致性、本人權限隔離、錯誤回滾、重複請求防重，以及真實瀏覽器遊玩驗收。這是「Web 新存檔持續可用」，不是「CGI 老存檔轉換」。
4. 原始 `log_dir/townlog*.cgi` 四份空白，只可當成原始世界佈局資料缺失的證據；現行 Web 單機試玩街區必須明確標示為 Web 配置，不冒充原版真實街道。**原始世界或商品表的讀取／比對**可以保留，與舊玩家資料匯入無關。

## 完全不做／不列待辦

- 不匯入或預覽舊玩家 `member/<ID>/log.cgi`、`mono.cgi`、`mail.cgi`、房屋／商店／銀行／裝備／信用卡／優惠券等私人存檔，也不轉換原 CGI 帳號、密碼、玩家 ID、歷史郵件或資產。
- 不為舊玩家存檔新增 API、資料庫映射、資料遷移、相容策略、匯入測試、真實玩家備份驗收或專門的「日後再補」事項；不得把此項寫成「仍未完成」以降低玩法完成度。
- 早期已存在的 `web/src/legacy-character.mjs`、`legacy-inventory.mjs` 匯入器與 `web/scripts/legacy-*.mjs` **只是歷史實作，不是目前的產品需求或使用步驟**。此政策不會藉修文件直接刪除資料表、移除現行物品使用引擎或破壞既有 Web 存檔。往後若安全清理未用匯入路徑，須另做可回滾且不影響 Web 玩家資產的技術維護。
- 「原版有 `mono.cgi` 的 33 欄」仍是**原版玩法資料格式證據**；現在新的 Web 物品表、扣耐久、獎品欄位不必為 CGI 角色歷史紀錄提供兼容。

## 文件判讀規則

第30、47、48、49、50、51階段的歷史稽核報告，若仍提到舊玩家匯入或舊檔實測，只能作為當時的技術紀錄，**已由本政策撤銷其未來工作要求**。本次同步修正文案與待辦，不把這些無需執行的事項列入新 PR 的驗收；目前玩法缺口仍需依真正原版執行分支如實標示。
