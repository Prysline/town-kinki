# 第 30 階段：根目錄 CGI／Perl 檔案第二層覆蓋率（2026-11-20）

> **現行範圍**：只重製原版玩法，不需要舊玩家存檔匯入、相容與真實舊玩家檔驗收；以 [專案範圍決策](project-scope-no-legacy-player-import.md) 為準。

> 依 `feature/web-dual-mode-phase1`、PR #33 後版本，以 Git tree 遍歷根目錄的 `*.cgi`／`*.pl` **67 個檔**，交叉比對 `migration-audit.md`、`phase30-open-audit-backlog.md`、`phase30-entrypoint-coverage.md` 的明確引用；此結果只是**檔案與原始程式來源覆蓋**，不是原版 67 個可玩設施。原版實際部署、真實玩家紀錄、所有管理員及多層 CGI 的函式仍需分層驗證。

## 交叉比對結果

- 67 個原始根目錄程式檔，先前三份清冊已有提到 **60 個檔名**，另 **7 個**尚未明確分類。這不表示 60 個已完成完整函式盤點；其中包含原始資料檔、外部依賴、空檔及未驗證可達性。
- 未明確分類的 7 個：
  - **`unei_2.pl`：確實與住宅玩法相依的來源**。[`original_house.cgi` L21](../../original_house.cgi#L21) 明確 `require './unei_2.pl'`，在 [L1586](../../original_house.cgi#L1586) 依內容位置呼叫 `&unei_2`；[`unei_2.pl::unei_2` L19 起](../../unei_2.pl#L19) 使用屋主個別 `member/<ID>/<slot>_log.cgi` 管理員工、最多 5 名、訓練消耗玩家能力、費用與冷卻，以及員工工作選項。Web 無此原版流程，新增 **HS-04 企業員工教育／員工紀錄**。該檔含數值判定、現金與銀行扣費問題，未經完整核對不可直接搬公式。
  - **`unit_temp.pl`：同版副本，不是新設施**。此 fork 與 `unit.pl` blob SHA 一樣；不把同一份 43 個表單入口重複列成 86 個。
  - **`check.cgi`：CGI 診斷用具，非遊戲功能**。檔案標題自稱 Perl CGI 執行檢查程式；讀取表單指定檔案內容並 `eval` 原始碼。**不移植為玩家功能，亦不應提供未受保護的診斷介面**。
  - **`host.cgi`：允許主機變更的管理輔助工具，非玩家遊戲功能**。檢查管理名稱、識別碼、密碼與輸入確認再改寫 `in_host.cgi`；此 fork 相關預設管理值為空字串，**不能模仿成對外開放的 Web 管理功能**。若原 CGI 同時營運，應另做安全審查。
  - **`dene2.cgi`、`guestlog_00.cgi`、`hostime.cgi`：三個 0 bytes 空檔**，沒有可執行程式內容。不得由檔名推定玩家功能；只有其他 CGI 的實際讀寫條件可證明它們是資料檔。
- 另有先前已分類的 0 bytes `atakka.cgi`：[`town_lib.pl::atakka` L43–86](../../town_lib.pl#L43) 的防濫用記錄檔，不是戰鬥程式。

## 盤點邊界及後續優先序

1. **確實漏列（加入待辦）**：HS-04 `unei_2.pl` 員工教育／名冊與工作門檻，先還原原始住宅內容位置、員工來源檔與費用／冷卻／權限，才能安排移植；包含單機／多人相容與交易回滾。此項屬 `HS-03` 企業／商用住宅的明確子功能，不能以 Web 已有房間留言就當完成。
2. **不列入玩家移植**：`check.cgi`、`host.cgi`、`unit_temp.pl` 副本及三個零位元組空檔；前兩項需另列**原站安全／營運資產**，不是原版可玩的設施。
3. **下一波逐層來源審核**：除了 `unit.pl` 首層 43 入口，還要掃 `town_maker.cgi`、`original_house.cgi`、`basic.cgi`、`gamerand.cgi`、`game.cgi` 等的次級 `mode/command`，記錄「呼叫路徑／可達性／輸入／資料檔／金流／Web 狀態」，但沒有原始執行依據時不得憑檔名杜撰。
4. **既定 P1 功能工作不中斷**：IT-04 優惠券獎品原始 33 欄解析已在 PR #33；下一步仍是原版持有物、Web 事件券的所有權與共同扣款交易，不因本檔清冊新發現而擅自插入其他玩法。
