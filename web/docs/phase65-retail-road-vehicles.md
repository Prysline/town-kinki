## 實作：同一種持久旅程，不另建交易

- `web/src/road-travel.mjs` 的 `parseOriginalRoadTransport(...,retailCatalog)` 以原版寶箱獎池 + 原版百貨目錄分開建置 `vehicles`、`retailVehicles`。五項百貨來源若行號、SKU、分類、效果、耐久單位、專門店限制或備註改變，直接拒絕靜默套用。
- 可選交通查詢從本人 `legacy_inventory_items` 與 `legacy_item_usage` 的33欄資料、目前耐久讀取，區分 `__web_treasure__`／`__web_retail__`。寶箱仍與原獎池逐項對照；百貨車除逐項對照原版商品33欄（只允許21耐久、26使用時間、30購入時間、31成本欄變動）外，**必須**有本人 `retail_purchases` 流水，且 `user_id`、`source_line`、`sku`、`name`、`shop=depart1/depart2` 一致。已經透過現有 Web 百貨購買且保持完整紀錄的舊車，更新後無須重購即可被辨識。
- 百貨同品追加購買原已允許折算及合併剩餘耐久；Web只接受安全保留的原版欄位並以 `inventoryLife` 判斷真實剩餘數量。歸零車不能出發。多人不能使用他人來源碼。
- 原 `POST /api/road/start`、`/api/road/arrive`、`arcade_road_trips` **完全不變更欄位**。前端仍只提交本人持有實體 `vehicleSourceLine`，**不接受自填原始車名、類別或假來源**。原車輛秒數、1/10事故、實際耐久扣1、自転車五能力鍛鍊、輪滑車從非3城必迷路、事故＋迷路改道、單一進行中行程、原子回滾與跨重啟均沿用舊功能。
- UI 在交通選單標記「百貨」或「寶箱」、當前耐久與秒數；其餘出發／抵達／歷史使用既有安全 `textContent` DOM，不新增可注入HTML的通路。單機21格、車站電車票價與巴士500元5秒均保持原狀。
