# 第58階段：遊樂中心原版六位數立即開獎樂透

日期：2026-11-21。功能分支 \`feature/web-phase58-instant-loto\` 基於 Web 整合分支 \`feature/web-dual-mode-phase1\` 最新提交 \`4bc516f9\`。原版 \`master\`、根目錄 Perl/CGI 和封存舊玩家資料均不修改。

## 一、選型、原版來源與其他兩種遊戲的狀態

- 原版 \`unit.pl\` 地圖「ゲーセン」→ \`gamerand.cgi\` 的 \`action="loto.cgi"\`、\`<>loto_game<>\` → \`loto.cgi::loto_game\`。與另一支 \`loto6.cgi\` 不同：此遊戲在玩家點下後**立即開獎、直接結算身上現金**，不延遲匯入普通銀行。
- \`loto6.cgi\` 的 \`$loto_n=36\`、\`$koniyukingaku=2500\`、\`$koushinjikan=6\`、\`$hitri_konu_zyougen=20\`：從 1～36 抽六個不重複號碼，依原版跨日／06:00判斷開獎，並對各買家寫入**普通銀行存款與銀行明細**。這是需要跨玩家共同時段結算的另一套流程，不可在本階段偽裝成即時開獎。
- \`fukubiki.cgi\` 原版明定起始 **2007-09-10 12:00**、結束 **2010-01-03 12:00**，非管理員測試情況下目前已到期。需要先持有「福引券」、每日一次、持有物上限等條件，獎品來自 \`dat_dir/keihin.cgi\`，\`$hazure_nashi='yes'\`，並存回本人 \`mono.cgi\`。此階段**不擅自延長活動日期、不憑空發券或獎品**。
- 此 fork 的 \`log_dir/loto_log.cgi\` 和 \`loto_kiroku.cgi\` 都是 0 bytes；不從虛空匯入既有遊玩者或成績。

## 二、即時樂透原版實際規則

| 內容 | 原版 \`loto.cgi\` |
|---|---|
| 六位數 | 玩家依順序選6個0～9數字，數字可以重複、允許前導0 |
| 開獎 | \`loto1\` 到 \`loto6\` 各自 \`int(rand(10))\`，**六個獨立等機率數字** |
| 猜中判定 | **只有相同位置**的數字相符才增加一位；不排序，不是「選6個不重複數字」 |
| 下注 | \`@loto_set3=('500','1000','5000','10000','50000','100000')\` |
| 配對 0、1、2、3、4、5、6 位 | 倍率依序 **0、2、5、20、100、500、1000** |
| 獎金 | 原版 \`$money = $money - $in{'rate'} + $in{'rate'} * $bai\`，即**先扣下注額，再發還下注額×倍率**；淨變化＝下注額×（倍率−1） |
| 連玩 | \`$loto_set1=1\`，\`$loto_set2=3\`分鐘；**只有上一個玩的人仍是本人**，才不能在三分鐘內再次進行。被其他玩家插入後同一人可立即再玩 |
| 負現金 | \`$loto_set4=0\`，不允許下注額高過現金；前端只展示有能力購買的倍率 |
| 共用紀錄 | \`$kirokuketa=0\`，零中獎也記錄；最多約50筆近況，\`loto_count\` 記錄總參與局數 |

注意 \`loto.cgi\` 同樣受 \`town_ini.cgi\` 的全域行動5秒限制，但 Web 其他小遊戲既有不同冷卻設計；本階段只嚴格實作 **loto 自己的上一玩家三分鐘限制**，未聲稱已將原版5秒限制接入所有設施。

## 三、Web 第58階段已接出的功能

- \`web/src/arcade-loto.mjs\` 啟動時解析並核對原版來源、六個獨立0～9抽號式、六個本金選項、七組倍率和上一遊玩者冷卻條件；原始規則改變時拒絕靜默運作。
- \`arcade_instant_loto_rounds\` SQLite 紀錄：\`user_id\`、唯一 \`request_id\`、下注額、六位選號與開出數字（JSON保存前導0）、配對位數、倍率、含本金總發還額、淨資產變化與時刻。全服**最後一筆局數**決定上一玩家是誰；每位本人另外只顯示最後20局，帳本不刪除超出20筆資料。
- \`POST /api/arcade/loto/play\` 只接受 \`stake\`、整數陣列 \`chosenDigits\`（剛好6位、0～9）和 \`requestId\`；伺服器逐位呼叫 \`crypto.randomInt(10)\`，客戶端不可傳入開獎結果、配對位數或任何收款額。依本人所在城鎮是否有 \`ゲーセン\`、實際現金、上一玩家、遊戲時間與合法注額核對，在 \`BEGIN IMMEDIATE\` 同一筆交易完成發獎、扣款及寫入結果；錯誤回滾，相同識別碼重送只取回原結果，不可改注額或選號。
- 沿用已建立的21格單機試玩街區 D9「ゲーセン」，不新增地圖格、不改已配置地圖；遊樂分頁與原有骰子及四卡牌面板並存，新增六個0～9選項、下注選單、確認提示、倒數與本人20局紀錄。畫面採 \`textContent\`，不使用自訂HTML組裝賭局結果。
- 與原版差異：對所有輸入進行伺服器強型別與合法選項驗證，防止在原始 CGI 直接POST任意數字、注額或破壞現金模型；阻止JS／SQLite安全整數溢出，並使用個人可見20筆歷史取代原版全服近50筆展示。單機玩家可以使用原有遊戲時間快轉三分鐘後繼續抽獎。
