## 原版來源及四種獎池

\`unit.pl::ゲーセン\` → \`gamerand.cgi\` \`action="otakara.cgi"\`／\`<>otakara<>\` → \`otakara.cgi::otakara\`。獎池來自 \`dat_dir/otakara.cgi\`，第一行33欄標題，實際110筆獎品；全部獎品保留原始33欄與原始類別、耐久及效果資料。

| 選箱 | 原版收費 | 該類原始資料列數 | 實際可抽候選 | 原因 |
|---|---:|---:|---:|---|
| 銅箱（\`銅の箱\`） | 500元 | 34 | **33** | \`int(rand($#dou_takaramono))\` 排除最後一筆 |
| 銀箱（\`銀の箱\`） | 1,000元 | 35 | **34** | \`int(rand($#gin_takaramono))\` 排除最後一筆 |
| 金箱（\`金の箱\`） | 2,500,000元 | 39 | **38** | \`int(rand($#kin_takaramono))\` 排除最後一筆 |
| 特殊箱（\`スペシャル\`） | 500,000元 | **全部110筆** | **109** | \`int(rand($#takaramono))\` 從全部獎池抽，排除其最後一筆 |

重要：特殊箱**不是**只從兩筆「スペシャル」類別獎品抽獎，而是讀入全部110筆獎品抽選。原始獎池最末項「究極の純プラチナカー」在特殊箱與金箱都無法抽中；Web 不擅自修復原始 off-by-one。此 fork 的 \`log_dir/otakara_log.cgi\` 以新 Web SQLite 獎勵帳本取代，不匯入原始 Perl 玩家歷史。

原版 \`$ota_rentou='yes'\` 允許同人續抽，但同人每次仍須間隔 \`$otakara_game_time=5\` 分鐘；開箱現金檢查 \`$motiganeseigen='yes'\`；原版整體基本行動間隔 \`$koudou_seigen='5'\` 秒。新 Web 僅提供寶箱專屬5分鐘控制，而不是全遊戲一體的Perl行動間隔。

## 真實獎品寫入，而不是文字或虛構獎勵

原版 \`otakara.cgi\` 的兩種執行分支：

1. \`$syo_kouka ne "無"\` 且非禮品／食品／速食效果 → \`takara_sutetasu\` 立即處理原始17項能力、疾病指數、體重／熱量與能量，並扣除開箱費。**當17項能力全部為0時**，原版 \`if ($print_messe eq "")\` 還會把獎品標價 \`$syo_nedan\` 加到身上現金。獎品「金塊」（原碼 \`ステータス\`、能力增量全0、標價5,000萬元）因此**不是取得實體金塊**：中獎時直接獲得5,000萬元，支付金箱費250萬元，淨得4750萬元。銀箱的「冷えピタクール」在原版同樣會發還其標價300元，並只在符合感冒病況時恢復7點疾病指數；不憑名稱假造治療所有疾病。
2. 效果 \`"無"\` 或走禮品／食品／速食分支 → \`buy_otakara\` 真正寫入 \`member/<k_id>/mono.cgi\` 原版33欄本人持有物，包含分類、能力、耐久、使用間隔、原始標價、購買時間等；原版相同物品「回／日」耐久合併並受 \`$item_kosuuseigen=5\` 倍上限限制。Web 對應到目前已使用的 \`legacy_inventory_items\` SQLite33欄資料及 \`legacy_item_usage\` 持有物生命週期，不另建假的寶箱背包。
3. 原版初始檢查一般物品25格，禮品10格及禮品商品限制，Web 於伺服器持有物現況核對；即使抽出直接生效獎勵也先檢查原版整體持有量，避免容量達上限時仍能繞過限制。現在出現來自多種 Web 來源的同名物品時，為保護不同來源的耐久紀錄，只在**寶箱來源同品**內進行合併；此點有別於原版透過名字及類別跨來源合併。
4. 33欄持有物的**後續使用**遵循 Web 現有 \`legacy-item-use.mjs\` 已驗證的原版消耗品安全子集。獎品如有道具效果仍未核實，保留原始所有欄位與名字、來源及耐久，並在背包顯示「未支援使用」，不假裝已具備未實作的交通工具、某些魔法或其他用途。真正可使用的背包物品沿用現有原版使用機制。

## Web API、資料與安全差異

- 新 \`web/src/arcade-treasure.mjs\` 啟動時核對 \`gamerand.cgi\`、\`otakara.cgi\`、\`dat_dir/otakara.cgi\` 與 \`town_ini.cgi\`，確認4種原始費用、5分鐘、同人可續抽、110筆類別數、33欄抽獎與末項排除機制；來源改動時拒絕靜默運作。
- \`POST /api/arcade/treasure/open\` 接受 \`boxKey=copper|silver|gold|special\` 與 \`requestId\`，不接受客戶端指定獎品、現金、效果或抽號。伺服器 \`crypto.randomInt(pool.length-1)\` 抽原始可抽候選，單筆 \`BEGIN IMMEDIATE\` 確認城鎮有遊樂中心、角色持有足額現金、背包容量、本人5分鐘間隔，更新現金／能力或33欄本人持有物，再寫寶箱交易歷史。任一步失敗全回滾。
- 新 \`arcade_treasure_rounds\` 每個帳號 \`request_id\` 唯一，保存寶箱、抽中來源、實際獎品名稱、扣款、是否入庫、直接現金獎勵、背包行號、能力／疾病效果摘要與時刻。防重送僅返回已完成的原局，變更箱種拒絕；本人畫面只列最近20筆，完整流水留存。
- 原版 \`mono.cgi\` 使用數十年舊檔與 Perl 檔案鎖，Web 僅操作新 Web 角色 SQLite 資料，保留一致的安全整數與原子性。Web 對欠款、無效值或上限改採拒絕（不允許負現金、負耐久或資料毀損）。
- 單機原有21格試玩地圖D9「ゲーセン」不變，遊樂中心原有八種模式不改。
- 此階段新增的完整寶箱**開箱與獎勵存取流程**已接通，但不能因此說原始所有物品的後續功能（例如金箱交通工具、所有魔法）都已移植完畢；也不聲稱整座遊樂中心已完全完成，原版福引活動仍於2010年到期。
