# 第 39 階段：原版「問屋」與本人住宅商店進貨、退貨（2026-11-20）

## 核對的原始依據

- `unit.pl` 第 158 行：「問屋」由 `command.pl::orosi` 開啟；只有有自己或配偶商店的角色才有進貨按鈕。貨物存到 `member/<店主ID>/omise_log.cgi`，**不是**一般持有物 `mono.cgi`。
- `original_house.cgi` 住宅室內的內容 `1` 是「お店」，店主可選 `town_ini.cgi::@global_syouhin_syubetu` 所列種類，後來變更商店類別會清除原本進貨。Web 先只實作**本人住宅**的商店；配偶代理進貨及對外銷售稍後另核實。
- `town_ini.cgi`：`$orosi_sinakazu=120`、`$ton_zaiko_tyousei=2`、`$mise_zaiko_gendo=100`、`$mise_zaiko_limit=100`、`$douitem_ok=0`。原版初始問屋商品檔 `log_dir/orosilog.cgi` 為空；新版由 `dat_dir/syouhin.cgi` 真實來源上架，不能憑空生成存貨。
- `command.pl::buy_orosi`：日常抽選最多 120 種（排除「食」與「デパート」），基本庫存乘 2；每次進貨數量須為正整數，不能超過本期共享貨架及每商品 100 件上限。商店僅可採購相同分類，除非設定「スーパー」，可跨類但進貨價乘 1.5，且不得購買專賣店限定和秘傳商品。付款由**普通銀行存款**扣除，記入普通帳簿。
- `tonyahenpin.cgi::henpin_do`：從本人店鋪庫存退貨，可指定數量，或輸入 0 全數退貨；普通店退還 `int(件數×商品批發標價×0.75)`，超市額外乘 `1.5`，退款進入普通銀行，不回補問屋共享庫存。該 CGI 是從**住宅商店設定**進入，所以不需要為退貨再次進入「問屋」。

## 目前實作

1. `web/src/rooms.mjs` 開放原版住宅室內欄位 `1`（玩家商店）；只有真的擁有 `houses` 房屋、於當前有效室內欄位設定商店、在該城鎮的屋主，才能再以 `/api/shop/config` 設定名稱和原版商店分類。
2. `web/src/wholesale.mjs` 自己解析來源 33 欄商品：獨立 `wholesale_day`、`wholesale_stock` 與 `player_shops`、`player_shop_stock`、`wholesale_transactions`。最多 120 種、來源庫存乘二、整服共用抽選及實際扣量；普通銀行扣款、超市特價倍率、分類與專賣店限制、每品與每店存量上限，都由伺服器驗證。
3. `/api/wholesale/buy`：要求所在城鎮地圖有「問屋」，進貨進入住宅商店專用庫存，不能直接進玩家背包。銀行餘額、共享貨架、店鋪存量、帳簿及買賣流水在同一筆 SQLite `BEGIN IMMEDIATE` 中提交，`requestId` 防重。
4. `/api/wholesale/return`：屋主住宅商店退貨，全部或部分退貨按原版 75% 公式，超市再乘 1.5，退款入普通銀行。**退貨不回補共用問屋貨架**。
5. 更改類別會清除商店庫存；若尚有庫存，Web 另要求明確確認後才能進行（原版會直接清除，這是避免誤觸的保護）。出售住宅會由 SQLite 外鍵移除該店及店鋪庫存，避免孤兒商店。
6. 地圖「問屋」現在有獨立入口與真正貨架、進貨數量、付款試算、住宅店鋪設定、進貨倉庫和退貨操作。住宅「玩家商店」欄位有對應導覽，而不是把店鋪當成一般留言板。

## 與原版尚未完全等價

- 原版每天**隨機時刻**換檔，由主城鎮時間旗標控制；Web 本階段定義為當地遊戲日期首次載入問屋時更新一次。這不是原版精確隨機時刻，未假裝一模一樣。
- 原版超市可有 .5 元的乘 1.5 價格，Web 普通銀行使用安全整數，對半元交易會**向上取整**，與原始 Perl 小數精度有差異。
- 原版支援配偶商店代理進貨及部分商品改名規則；Web 此次只允許本人有真實住宅與店鋪的狀態，未假造配偶授權。
- **玩家自家商店對外零售**、銷售價格上下限、買家付款、店主銀行入帳與現金回饋仍要另讀 `original_house.cgi` 與 `command.pl::buy_syouhin`，本次不把「進貨完成」誤報成「店舖整套經營完成」。
- 原版匯入的 `member/<id>/omise_ini.cgi`、`omise_log.cgi` 與原始住宅舊存檔尚未做可寫遷移；現有 Web 資料獨立。真正瀏覽器實機及原版歷史玩家檔尚未驗收。
