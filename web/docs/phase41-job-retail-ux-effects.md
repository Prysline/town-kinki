# 第 41 階段：職業條件對照、百貨商品結帳排版與原版效果補全（2026-11-20）

## 使用者回報與根因

1. **職業要求能力失去「本人目前能力」資訊**：`web/public/app.js::jobRequirementsPanel` 原本已從 `state.character.stats[key]` 讀取並比較，卻只顯示 `labels[key] + "：要求 " + required`。需求判定仍存在，但 UI 漏掉本人數值。改成每欄「目前／要求／已達標或還差 N」，收合標題也直接顯示符合門檻數；BMI／身高一併附目前值，不改後端資格規則。
2. **百貨選項垂直堆疊**：原商品卡片為 `flex-direction:column`，數量、付款方式各自成為全寬的直列標籤與選單。新 `retail-buy-controls` 將兩組選單排成一列，並拉大商品卡片合理寬度；上方百貨分店／搜尋也使用兩欄並排，極窄螢幕仍可自然換行。介面更動不改原版價格、購買份數或付款檢查。
3. **百貨商品看不到具體效果**：`dat_dir/syouhin.cgi` 的原版商品實際保有 **33 欄**。符合目前 Web 百貨解析器條件的 **416 筆**原始非食堂商品中：**374 筆含非零能力增減值、64 筆有非「無」的特殊效果代碼、186 筆有備註、280 筆有非零熱量或身體／頭腦能量消耗欄位**（互相重疊，不可加總）。舊 `web/src/retail.mjs::listRetailStock` 只公開商品名稱、類別、價格、庫存與耐久，**沒有傳回原版已有的使用效果欄位**；這是 Web 顯示遺漏，不是原版完全沒寫。

## 原版來源與資料解讀

- `web/src/legacy-inventory.mjs::LEGACY_ITEM_FIELDS` 定義原版 33 欄位置：第 3～9、11～17、19～21 欄為 17 種能力變動；第 10 欄為 `effect`；第 24 欄為使用間隔；第 26 欄為熱量；第 28、29 欄為身體／頭腦能量消耗；第 30 欄為文字備註（這裡均採**人類從 1 開始計數**，程式的陣列索引少 1）。
- `basic.cgi::item_do` 確實會套用上述能力增減與依情況適用的疾病／體重／身高特殊效果，同時扣除或恢復能量、改變體重。**原版效果代碼 `無` 不代表能力增減也為零。**
- 例如原版 `油取り紙` 為外貌（looks）+2、使用間隔 10 分鐘、特殊欄 `無`；原版 `元気ミルク` 的身體能量消耗為 **-500**，代表能量恢復，備註也寫明 `身体消費が回復します。`；`健康保険` 在 Web 醫院自動生效；`クレジットカード` 則用於已有支援的有效卡片普通銀行付款。
- `web/src/legacy-item-use.mjs` 目前只有核對過的安全使用白名單，並**不**代表 `dat_dir/syouhin.cgi` 中所有已記載的特殊效果都在 Web 可以用。新商品明細將「原版數值／備註」與「Web 已支援手動使用、醫院自動生效、有效信用卡付款、禮品操作、尚未支援」清楚區分，且支援狀態復用正式使用白名單，不自行猜測效果。
- 原版未註明文字用途的商品照實呈現「沒有提供文字備註」；只列原版確實有的能力／特殊代碼，不補寫世界觀或假設的用途。

## 修改範圍

- `web/src/legacy-item-use.mjs`：導出原版使用白名單的唯讀預檢。
- `web/src/retail.mjs`：將原版資料解析成欄位化商品說明 `details`，列入百貨 API（不外流完整 33 欄）。
- `web/public/app.js`：職業要求本人值與差額；百貨商品完整明細、使用狀態及並排購買選項。
- `web/public/index.html`、`web/public/style.css`：百貨搜尋與結帳響應式排版，增補說明。
- `web/tests/retail.test.mjs` 與 `web/tests/home-ui.test.mjs`：核對原版例子、白名單／自動效果與 UI 不再省略本人值。

## 邊界

- 本階段是 **還原商品效果資訊的可見性與修復版面**，不會假裝所有 416 筆效果都已執行。未實作的原版特殊效果仍需另外逐種核對 `basic.cgi`、贈禮及其他設施。
- 物品原始匯入存檔保持唯讀，不變更交易公式／銀行餘額／庫存／使用效果計算，也不修改 `master`。
