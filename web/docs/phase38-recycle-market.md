# 第 38 階段：原版「リサイ」回收商店二手市場（2026-11-20）

## 原版來源核對

- `unit.pl` 第 148 行：「リサイ」建築進入 `recycle.cgi::resycle`。
- `recycle.cgi` 第 7～17 行：全服 `log_dir/recycle_log.cgi`、回收上限 200,000、貨架最多 50 筆、最多保留 7 天、允許出售禮品、售出前須等 30 分鐘。
- `recycle.cgi::baikyaku_do`：出售的耐久若為「日」，先減去已過天數，並要求至少經過一整天；「回」用目前剩餘次數。賣價為第 32 欄單位價格 × 剩餘耐久，最高 200,000。若超出上限，原程式將後續轉售單價調成 `int((200000 / 剩餘耐久) × 0.8)`。
- `recycle.cgi::resycle_do`：其他玩家以貨架商品的新單價 × 耐久支付現金；購買一筆後商品從貨架移除，一般商品分類改為 `リサイクル`，食料品與速食類維持原分類，購入時間刷新。原始 CGI 直接減現金而沒有檢查餘額，Web 為防止負數加上付款限制。
- `log_dir/recycle_log.cgi` 在目前的 fork 是空檔案，不宣稱有任何既存二手庫存。Web 空白貨架須由真實玩家先出售物品產生。

## 本次功能

1. `web/src/recycle.mjs` 新增獨立 `recycle_listings` 與 `recycle_transactions`。只處理本人 Web 購物、收禮或回收取得的 33 欄物品（原始 `mono.cgi` 匯入不改寫）。
2. 回收出售：所在城鎮必須設有「リサイ」，依原版購入後 30 分鐘、日制需滿一日、剩餘耐久及單價計算收入；出售後整筆物品離開賣家背包，依原版價格上架全服二手貨架。
3. 貨架只保留最新 50 筆，超出保留 7 天期限的商品從可售區移除；市場交易一物只能被一人購入。已過期或被擠掉的貨品不自動退回原賣家，沿用原版風險。
4. 回收購買：買家現金足額、一般持有物格數限制 25、商品仍在未過期貨架，才在同一 SQLite 交易扣款、移除貨架商品並以 `__web_recycle__` 來源加入本人 33 欄持有物。
5. 交易、扣款、入庫與貨架狀態在 `BEGIN IMMEDIATE` 內一起更新，`requestId` 防止重複購買或重複回收。二手購入物不會被當作百貨原價商品；若後續轉禮品，則仍可走 Web 禮品轉換。
6. 地圖「リサイ」現在導向回收商店專屬的二手貨架／出售本人持有物／交易歷史面板。

## 尚未全等

- 原版 `recycle.cgi` 以 CGI 檔案日期及陣列位置保存二手貨架，Web 使用 SQLite 主鍵。經歷過 50 筆淘汰或七天後，只依當前有效清單展示，不會重新讀取歷史原版 log。
- 原版允許缺錢仍直接扣現金，本 Web 明確禁止讓角色現金成為負數。
- 原版出售有些情況會嘗試更新禮品的種類與註解、消除無耐久的檔案列；Web 本次只修改本人已驗證的 Web 來源品，舊原始資料唯讀。
- 回收特殊商品的效果仍只能走 `legacy-item-use.mjs` 已核對的安全白名單，戰鬥、商店、合成效果未憑空新增。
- 尚未進行人工瀏覽器、真實原版歷史玩家檔案與高負載並行實測。
