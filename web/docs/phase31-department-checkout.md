# 第 31 階段：百貨店購買數量、同品耐久、原版信用卡與禮品容量（2026-11-20）

## 原版核對

- `command.pl::depart_gamen` 及 `::buy_syouhin`：數量依 `$item_kosuuseigen` 1～5、相同一般商品合併 `回`／`日` 耐久；普通 25 格與禮品另計。
- `town_ini.cgi`：`$item_kosuuseigen=5`、`$syoyuu_gendosuu=25`、`$kounyu_gift_gendo=10`。
- `command.pl` 支援本人持有效原版「クレジット」道具改用普通銀行存款付款；本版引用既有 `legacy-credit.mjs` 真實持有物與有效期限驗證，不接受前端聲稱信用卡有效。
- 原版隨機發優惠券、贈送／轉手商品與個人商店金流不屬於本次切片。

## 本次已完成

1. `POST /api/retail/buy` 可傳 `quantity`（1～5）及 `payment: "cash"|"bank"`，選銀行付款需提供本人有效 `cardSourceLine`。舊客戶未送數量／付款方式仍採現金 1 件。
2. 伺服器在 `BEGIN IMMEDIATE` 中核對所在地實體百貨、上架量、總金額、個人有效卡片、普通存款，完成庫存扣量、金額扣款（信用付款含銀行帳簿）、道具耐久入庫及單筆紀錄。失敗回滾，`requestId` 不得改商品、數量或付款方式後重用。
3. 舊 Web 新購的同名、同分類、同效果、同耐久單位一般物品會安全累加；`回` 保留已使用剩餘次數與冷卻紀錄，`日` 按目前剩餘有效日數重新計算起日；可合併的同品總量不得超過五組。
4. 購入禮品獨立以最多 10 個持有列計算，不與一般的 25 格互搶。禮品不合併，單筆數量記在耐久中；原版對禮品轉贈流程尚待移植。
5. `retail_purchases` 安全升級舊資料（預設一件、現金付款），補記每筆購買數量、信用付款來源與耐久合併；Web 可選數量／本人有效卡片並查閱購物紀錄。

## 保留界線與未完成

- **舊版原始匯入的 `mono.cgi` 仍為唯讀封存。** 即使商品名稱相同，也不修改或混合其 33 欄資料；原版可以直接合併舊物品的全部邏輯仍待獨立相容性處理。
- 舊 Web 在第 30 階段曾為同品建立多列；本次會合併至第一筆尚可容納的 Web 物品，不批次改寫既有購買紀錄或使用歷史。
- 可購買並不保證道具全部效果、裝備／禮品使用、轉讓或賣出可用；特殊效果仍受 `legacy-item-use.mjs` 的安全白名單限制。
- 原版同城／異城限制、私人店家現金回饋、購物贈券、所有原版特殊品項命名與真實舊角色存檔、實機瀏覽器驗收仍未完成，不能宣稱 100% 等價。
- 下一步依建築優先政策，先檢查多件與信用交易在真實來源的差異，再實作自動販賣機的獨立價格／庫存與交易流程。
