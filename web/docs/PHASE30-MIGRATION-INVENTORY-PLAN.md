## 執行順序與完成標準

### A. 先交完整盤點（第 30 階段的第一個交付物）

請建立 `web/docs/migration-audit.md`（**與本「計畫」文件分開**），按下列格式逐項盤點，並在 README 連結。

| 欄位 | 必填內容 |
| --- | --- |
| 功能 ID／名稱 | 可追蹤且不重複的代碼，分拆到足以驗收的單一功能 |
| 原版來源 | Perl/CGI 檔名、函式／分支、資料欄位／原始商品資料、檔案行段；若缺資料標「未知」 |
| Web 現況 | 模組／API／前端容器／資料表／測試；區分已合併主整合分支與未合併 PR |
| 完成度 | **已完成／部分完成／未實作／缺少來源無法驗證／暫不移植** |
| 差異與風險 | 原版值 vs Web 值；冷卻、隨機、資產、權限、儲存、UI、相容性、安全邊界 |
| 優先度與阻塞 | P0／P1／P2、相依功能與需要的真實存檔／素材 |
| 實作細項 | 明確寫出邏輯、API、SQLite 遷移、UI、資料匯入／匯出及必備例外處理 |
| 驗收證據 | 已有測試／需新增測試、需要的真實瀏覽器尺寸與操作檢查、CI 結果 |
| 預定階段 | 第 30／31／後續階段與獨立 PR，未確認時寫待排定 |
